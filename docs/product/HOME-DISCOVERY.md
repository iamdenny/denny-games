# 홈 게임 탐색 개선 PRD

작성일: 2026-10-21 · 상태: 구현·로컬 검증 완료

## 1. 문제와 근거

현재 공개 홈과 저장소를 확인한 결과, 사이트 안에서 실행되는 게임은 207개다. 히어로는 전체 로컬 게임을 무작위 순서로 소개하며 8초 자동 넘김, 멈춤·다음 게임과 플레이 방식 선택을 제공한다. 이 기능은 이번 개발의 출발점이다.

홈은 에디터 추천 6개 다음에 7개 장르의 게임을 3개씩 보여준다. 장르 목록에도 에디터 우선 정렬을 적용하기 때문에 오빗 브레이크, 서킷 루프, Bounce Back, UNDERRUN, SKY GOLF, 오목이 반복된다. 이 두 영역의 카드 27개가 소개하는 고유 게임은 21개다. 히어로, 게임 모음의 썸네일과 최근 플레이 영역은 이 계산에서 제외한다.

이 중복은 같은 스크롤 길이에서 발견할 수 있는 게임 수를 줄인다. 방문자가 실제로 다양성이 부족하다고 느끼는지, 이 변경이 방문·플레이·재방문을 늘리는지는 아직 측정하지 않았다.

근거 코드: [홈 구성](../../src/pages/[locale]/[...path].astro), [에디터 순서](../../src/data/editorial.ts), [장르 목록](../../src/data/games.ts), [히어로](../../src/components/QuickPlay.astro).

## 2. 목표와 대상

처음 온 방문자는 서로 다른 게임을 비교하고 바로 플레이할 수 있어야 한다. 다시 온 방문자는 최근 플레이와 보관함으로 쉽게 돌아갈 수 있어야 한다. 장르를 정한 방문자는 미리보기에서 관심을 확인하고 전체 장르 목록으로 이동할 수 있어야 한다.

이번 릴리스의 목표는 에디터 추천과 장르 미리보기 사이의 중복을 없애는 것이다. 현재 데이터 기준으로 같은 27개 카드 자리에 고유 게임 27개를 소개한다. 신규 게임 등록이나 카탈로그 수 증가를 성과로 삼지 않는다.

## 3. 화면 구성과 사용자 흐름

홈의 기존 순서를 따른다.

1. 짧은 소개, 전체 게임 수와 검색.
2. 전체 게임을 소개하는 히어로, 플레이 방식 선택, 장르 바로가기와 최근 플레이.
3. 게임 모음과 처음 하는 사람을 위한 규칙 안내.
4. 에디터 추천 6개.
5. 앞의 추천과 겹치지 않는 장르별 미리보기.
6. 오늘의 도전 진행, 기존 광고·제휴 영역과 플레이 노트.

추천에서 관심 게임을 발견하면 바로 플레이하거나 소개를 읽는다. 장르 미리보기에서는 서로 다른 게임을 살펴보고, 더 찾고 싶으면 해당 장르의 전체 목록으로 이동한다. 전체 게임과 검색은 홈 상단에서 계속 접근할 수 있어야 한다.

## 4. 기능 요구사항

| ID  | 요구사항                            | 완료 조건                                                                                                                                                                                       |
| --- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H01 | 추천 영역과 장르 미리보기 중복 제거 | 실제 추천 영역에 선택된 게임 ID를 모든 장르 미리보기에서 제외한다. 현재 데이터에서 두 영역 전체 27개 카드의 ID가 모두 다르다.                                                                   |
| H02 | 안정적인 장르 선택                  | 장르의 기존 편집 순서에서 제외 대상만 걸러낸 뒤 최대 3개를 선택한다. 빌드마다 무작위로 바꾸지 않는다. 전체 장르 목록의 정렬은 기존 규칙을 따른다.                                               |
| H03 | 데이터 증감 대응                    | 추천은 최대 6개, 장르 미리보기는 제외 후 남은 수와 3 중 작은 수만 표시한다. 부족한 자리를 중복·가짜 게임으로 채우지 않는다.                                                                     |
| H04 | 작은 장르의 탐색 보장               | 제외 후 미리보기가 0개인 장르는 빈 카드 그리드 없이 장르명·실제 전체 수·전체 보기 링크를 제공한다. 공개 게임이 없는 장르는 홈에 노출하지 않는다.                                                |
| H05 | 정확한 수량 표현                    | 장르 제목의 수는 미리보기 수가 아닌 해당 장르의 전체 공개 게임 수다. 추천 개수 문구는 실제 렌더링 수에서 생성한다. 207이나 27을 제품 코드에 고정하지 않는다.                                    |
| H06 | 한 번에 플레이                      | 장르 미리보기 카드에도 추천 카드와 같은 명확한 바로 플레이 동작을 제공한다. 제목·이미지는 게임 소개로, 바로 플레이는 동일 게임의 사이트 내부 플레이 경로로 연결한다. 저장 버튼은 별도 동작이다. |
| H07 | 언어와 접근성                       | 새 문구·동작 이름을 한국어와 영어로 제공한다. 터치와 키보드로 소개·플레이·저장을 구분해 선택할 수 있고 포커스가 보인다. 카드 안에 링크·버튼을 중첩하지 않는다.                                  |
| H08 | 정적 탐색                           | JavaScript 없이도 추천·장르 카드, 소개·플레이 및 전체 보기 링크를 이용할 수 있다. 게임 실행 자체의 JavaScript 요구와 구분한다.                                                                  |

### 중복 제거의 경계

히어로는 전체 로컬 게임에서 추첨한다. 자동 넘김에 맞춰 아래 카드가 바뀌거나 사라지지 않으며, 히어로 게임이 아래에 등장하는 것은 허용한다. 최근 플레이와 게임 모음의 썸네일도 각각 복귀와 모음 설명을 위한 영역이므로 중복 제거 대상에 넣지 않는다.

장르 미리보기는 별도의 홈 선택 규칙을 사용한다. 전체 카탈로그·장르 상세·검색의 게임 수, 정렬과 페이지 범위에 홈의 제외 규칙이 영향을 주어서는 안 된다.

## 5. 시각·모바일 요구사항

Arcade Press의 색상·서체·카드와 여백 규칙을 따른다. 이번 변경에서 홈에 새 섹션이나 추가 카드 행을 만들지 않는다. 기존 카드 공간에 서로 다른 게임을 보여주며, 새 바로 플레이 동작은 기존 추천 카드 패턴을 재사용한다.

320·360·390·430px 휴대폰 폭, 810×1080 및 1080×810 태블릿 뷰포트, 1440×900 데스크톱에서 확인한다. 긴 한·영 제목에도 이미지 비율과 카드 동작을 유지하고 페이지 가로 넘침이 없어야 한다. 플레이·저장 동작은 최소 48px 터치 영역을 제공하며 hover 없이 찾을 수 있어야 한다.

뷰포트 검사 결과는 실제 iPad·iPhone·Android 또는 Tesla에서 조작을 확인한 결과와 따로 기록한다.

## 6. 검색·성능·개인정보 요구사항

기존 언어별 홈 URL과 canonical·hreflang을 유지한다. 홈의 구조화 데이터에 게임 목록을 포함하는 경우 실제 표시 카드와 일치시킨다. 장르·전체 카탈로그·게임 상세 페이지로 이어지는 정적 링크를 유지한다.

게임 엔진은 홈 번들에 포함하지 않는다. 새 추천 API나 외부 요청 없이 레지스트리에서 빌드 시 카드 목록을 결정한다. 이미지 크기·로딩 우선순위는 기존 카드 규칙을 따른다.

검색어·게임 선택·점수·저장 상태를 보내는 분석 이벤트를 추가하지 않는다. 동의한 페이지 조회만 보내는 기존 정책을 따른다. 카드 다양성 개선을 검색 순위·인기·재방문 증가로 표현하지 않는다.

| 구분        | 확인할 결과                                                                                                                               |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 데이터 선택 | 두 영역의 중복 ID가 0개다. 각 미리보기 게임이 해당 장르와 공개 로컬 레지스트리에 속한다.                                                  |
| 경계 데이터 | 작은 장르, 추천이 적은 경우, 제외 후 0개인 장르 및 비공개 1,000개 fixture에서 수량·링크·빈 상태가 정확하다.                               |
| 실제 데이터 | 현재 스냅샷에서 추천 6개와 장르 미리보기 21개가 고유 게임 27개를 표시한다. 카탈로그 변경 후에는 같은 규칙으로 기대값을 다시 계산한다.     |
| 사용자 흐름 | 양 언어에서 소개·바로 플레이·저장·장르 전체 보기와 상단 검색이 올바른 대상으로 연결된다. JavaScript 없는 탐색도 확인한다.                 |
| 기존 기능   | 히어로 전체 게임 풀과 자동 넘김·멈춤, 최근 플레이, 보관함, 일일 도전 및 전체 카탈로그 범위가 정상이다.                                    |
| 화면        | 위 휴대폰·태블릿·데스크톱 뷰포트에서 긴 제목, 터치 영역, 키보드 포커스와 가로 넘침을 확인한다.                                            |
| 배포        | 저장소 필수 검사와 브라우저 검사를 통과하고 리뷰 후 PR을 머지한다. Pages 완료 뒤 공개 한·영 홈의 카드·링크와 release SHA를 읽어 확인한다. |

구현은 추천 6개와 장르 미리보기의 중복 ID를 제외하도록 적용했다. 현재 검증 결과는 `npm run verify` 통과(타입 오류 0, Vitest 77개, 문서 76개, 1,000개 카탈로그 fixture, 926개 정적 페이지)와 `PLAYWRIGHT_PORT=49027 npm run test:e2e` 통과(Chromium 514개)다. 브라우저 검사는 양 언어와 320–1440px 휴대폰·태블릿·데스크톱 뷰포트를 포함한다. Astro가 보고한 기존 `tests/e2e/discovery.spec.ts`의 미사용 변수 hint 1개는 남아 있다.

이 결과는 로컬 코드·정적 빌드·Chromium 자동화에 한정된다. CI 리뷰, Pages 배포, 공개 release SHA와 카드 링크 확인은 PR 머지 후 별도로 확인한다. 실제 iPad·휴대폰 조작은 이 뷰포트 검사로 완료 처리하지 않는다. 홈 탐색 변경은 [ADR 0041](../adr/0041-distinct-home-discovery-previews.md), 다단계 게임의 단계 표시와 다음 판 흐름은 [ADR 0042](../adr/0042-visible-multi-stage-progression.md)에 기록했다.
